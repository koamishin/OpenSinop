Start with a simulated evaluation. Add provider credentials and network payment
capabilities only after a separately approved review.

For a host installation, settings usually come from `.env`. The current Docker Compose
file loads `.env` for the app and has an explicit environment block that takes
precedence. Review each service's effective values. Laravel's cached configuration can keep old values:
refresh configuration and restart long-lived web/worker processes after changes.

## Evaluation checklist

```dotenv
LEPTON_DRIVER=fake
LEPTON_WEBHOOKS_ENABLED=false
EDUFLOW_AUTONOMOUS_PIPELINE_ENABLED=false
EDUFLOW_AUTONOMOUS_PIPELINE_AUTO_DISBURSE=false
EDUFLOW_SUBMISSION_ENABLED=false
EDUFLOW_SUBMISSION_STOP=true
EDUFLOW_TUITION_SUBMISSION_ENABLED=false
EDUFLOW_TUITION_OBSERVATION_ENABLED=false
EDUFLOW_TUITION_AUTO_INTAKE=false
EDUFLOW_BILL_SUBMISSION_ENABLED=false
EDUFLOW_BILL_OBSERVATION_ENABLED=false
EDUFLOW_BILL_AUTO_INTAKE=false
EDUFLOW_MANDATE_ENABLED=false

```

Keep signing credentials out of the evaluation instance. Bridge inspection does not
replace independent receipt or payment review. See [Current limits](../../institution/safety-readiness/).

## School identity and access

Use `app:install` to persist the institution name, country, locale, timezone, and
currency. English is the supported installation locale. Repeating identical setup is
a no-op; changing existing identity is refused rather than overwritten.

The persisted institution is the normal selection. `EDUFLOW_INSTITUTION_ID` is an
optional explicit binding for legacy setups; if present, it must match. Do not select
an arbitrary first organization or host unrelated schools in one database.

The installer disables public registration, impersonation, and advisory AI settings.
Those settings are distinct from wallet and bridge runtime flags. School currency
metadata also does not convert existing monetary records.

## Web, database, mail, and jobs

| Setting | What to decide |
| --- | --- |
| `APP_ENV`, `APP_DEBUG` | Use `production` and `false` on a deployed instance. |
| `APP_URL` | Your actual application address, used in links and mail. |
| `APP_KEY` | Generate once for a new instance. Preserve it in backups. |
| `DB_CONNECTION` and credentials | SQLite locally; supplied Compose uses PostgreSQL. |
| `MAIL_*` | Working email verification and recovery delivery before staff access. |
| `QUEUE_CONNECTION` | A durable `database` or `redis` connection. `sync` is not valid for these background finance workflows. |
| `CACHE_STORE`, `SESSION_DRIVER` | Durable, appropriately shared stores for the deployed processes. |

Planning and receipt routing are currently set to `true` directly in
`config/eduflow.php`. **`EDUFLOW_BACKGROUND_FINANCE` and
`EDUFLOW_FINANCE_QUEUE_CONNECTION` are not read there.** Planning uses the default
queue connection; jobs such as policy evaluation also use its default queue.

See [Run background services](../../guides/operations/) for named payment queues and
the required retry/timeout relationship.

## Background receipt and advisory configuration

The legacy bridge flags default off and its implementation is read-only. No flag
creates payment authorization, staff accounts or MFA evidence.

- `EDUFLOW_TUITION_INTAKE_OWNER_ID`: existing verified institution finance owner, never payer.
- `EDUFLOW_AUTONOMOUS_PIPELINE_REVIEWER_ID`: explicitly configured existing institution admin requester for background receipt classification; not a payment approver impersonation.
- Advisory and disclosure are separate operator settings. Enable both only after approving provider data sharing.
- Database/Redis queues must have `retry_after` greater than job timeout (120 seconds for assistance commentary; 180 for institution policy evaluation).

## Optional wallet connection

For an approved Arc Testnet experiment, verify the actual treasury address and custody
model before supplying credentials:

```dotenv
LEPTON_DRIVER=circle
LEPTON_CIRCLE_BIN=circle
LEPTON_ARC_BIN=arc-canteen
LEPTON_CHAIN=ARC-TESTNET
LEPTON_CHAIN_ID=5042002
LEPTON_TREASURY_ADDRESS=
LEPTON_RPC_URL=
```

`circle` uses the agent-wallet integration; `developer` / `circle-rest` select a
different custody/API integration. They are not interchangeable access to the same
wallets. The locked package is Lepton `v3.0.0-rc.1`, a prerelease.

`LEPTON_CIRCLE_API_KEY`, `LEPTON_ENTITY_SECRET`, and `LEPTON_WALLET_SET_ID` belong to
the developer-wallet configuration. Do not assume adding them enables an approved
payment rail: current developer-wallet execution in the payment transport is blocked
pending reviewed fee controls.

Run `php artisan lepton:doctor --skip-transfer` for read-only diagnostics. Do not add
transfer or wallet-adoption options unless separately authorized.

## Payment and observation switches

All submission/observation switches below default off. Stop switches default false;
set them deliberately if stopping new sends is your intent.

| Purpose | Settings |
| --- | --- |
| Reviewed vendor submissions | `EDUFLOW_SUBMISSION_ENABLED`, `EDUFLOW_SUBMISSION_STOP`, `EDUFLOW_SUBMISSION_QUEUE_CONNECTION` |
| Student tuition | `EDUFLOW_TUITION_SUBMISSION_ENABLED`, `EDUFLOW_TUITION_OBSERVATION_ENABLED`, `EDUFLOW_TUITION_SUBMISSION_STOP`, `EDUFLOW_TUITION_QUEUE_CONNECTION` |
| Student campus bills | `EDUFLOW_BILL_SUBMISSION_ENABLED`, `EDUFLOW_BILL_OBSERVATION_ENABLED`, `EDUFLOW_BILL_SUBMISSION_STOP`, `EDUFLOW_BILL_QUEUE_CONNECTION` |
| Receipt intake | `EDUFLOW_TUITION_AUTO_INTAKE`, `EDUFLOW_BILL_AUTO_INTAKE`, with named intake owners |
| Recurring mandate checks | `EDUFLOW_MANDATE_ENABLED`, `EDUFLOW_MANDATE_ALLOWANCE`, `EDUFLOW_MANDATE_QUEUE_CONNECTION` |

Student network sends additionally require explicit account or bill allowlists
(`EDUFLOW_TUITION_PILOT_ACCOUNT_IDS`, `EDUFLOW_BILL_PILOT_IDS`), appropriate recovery
owners, valid consent, and the correct rail. Setting a flag alone does not satisfy them.

Keep observation and recovery available for existing uncertain attempts when stopping
new payments. Turning off everything or deleting pending records can hide unresolved work.

## Optional AI providers

Configure providers in **Settings → AI Providers**, and review the disclosure and
advisory switches in **Settings → AI**. API keys are encrypted using `APP_KEY` and are
not shown back in the edit form.

For an OpenAI-compatible endpoint, the relevant environment names are:

```dotenv
AI_PROVIDER=local
AI_LOCAL_URL=http://localhost:11434/v1
AI_LOCAL_MODEL=your-installed-model
AI_LOCAL_API_KEY=
```

The generic alternative uses `OPENAI_COMPATIBLE_URL`,
`OPENAI_COMPATIBLE_MODEL`, and `OPENAI_COMPATIBLE_API_KEY`.
Model names depend on your provider; no particular model is required by this handbook.

`EDUFLOW_INSTITUTION_POLICY_ADVICE` controls institution policy advice, and
`EDUFLOW_POLICY_CLASSIFICATION_ENGINE` selects `text` or `jev`. The repository's
`.env.example` differs from some code defaults; inspect effective configuration rather
than assuming every AI setting is off. Publication/evaluation workflows may require a
configured provider even though manual collections and deterministic planning do not.

## Webhook ingestion

Keep `LEPTON_WEBHOOKS_ENABLED=false` unless configuring a reviewed developer-wallet
notification integration. The handler requires a `developer`/`circle-rest` driver,
signature headers, allowed subscription IDs, valid event/network identity, and a durable
queue. Set `LEPTON_WEBHOOK_SUBSCRIPTIONS` explicitly.

Verification stores a notification and queues observation. It does not authorize or
settle a payment.

## Campus quick resources

Student resource cards are configured under `resources` in `config/eduflow.php`.
Cards without a URL stay inactive. Set real library, calendar, help, and office URLs
instead of linking placeholder buttons.
